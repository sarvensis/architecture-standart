| **Код** | **Требования**                                                                      | **Комментарий**                                                                                                 |
|---------|-------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------|
| F       | Функциональные (Functionality)                                                      |                                                                                                                 |
| F1      | Клиент может подать заявку на депозит через сайт и интернет-банк                    | Это ключевая функция MVP. Сайт — только контактная информация, интернет-банк — полный процесс с подтверждением. |
| F2      | В интернет-банке отображаются персонализированные ставки                            | Для этого необходима интеграция с АБС или новым модулем расчёта ставок.                                         |
| F3      | Заявка на депозит передаётся в систему кол-центра                                   | Это позволяет менеджеру обработать запрос и предложить клиенту особые условия.                                  |
| F4      | Обработка заявки происходит в АБС сотрудником бэк-офиса                             | Пока не автоматизировано, но должно быть подготовлено к будущей автоматизации.                                  |
| F5      | Подтверждение операции через СМС-код в интернет-банке                               | Использование существующего механизма СМС, желательно без изменений со стороны подрядчика.                      |
| F6      | Отправка уведомлений о подтверждении ставки и открытии депозита через СМС           | Интеграция с СМС-шлюзом. Должна быть реализована в АБС или промежуточном сервисе.                               |
| F7      | Шифрование данных при передаче между клиентом и серверами                           | TLS/HTTPS обязательны для сайта и интернет-банка. Защита персональных данных.                                   |
| U       | Удобство использования (Usability)                                                  |                                                                                                                 |
| U1      | Интерфейс должен соответствовать корпоративной системе дизайна                      | Чтобы пользователи чувствовали единое пространство.                                                             |
| U2      | Все операции должны выполняться за минимальное количество шагов                     | Особенно важно для старшей возрастной группы.                                                                   |
| U3      | Операции должны быть понятны и интуитивно логичны                                   | Нужны четкие названия, подсказки и валидация форм.                                                              |
| U4      | Система должна предоставлять обратную связь после каждой операции                   | Например: "Заявка отправлена", "Дождитесь звонка".                                                              |
| R       | Надёжность (Reliability)                                                            |                                                                                                                 |
| R1      | Сервисы должны быть доступны 99.9% времени                                          | Это требование относится к интернет-банку и системе кол-центра.                                                 |
| R2      | Должна быть обеспечена отказоустойчивость интернет-банка                            | Возможность переключения на резервный ЦОД                                                                       |
| R3      | Необходима защита от потери данных при сбое системы                                 | Логирование и транзакции при работе с заявками и СМС.                                                           |
| R4      | Работоспособность АБС не должна нарушаться при увеличении нагрузки                  | Предусмотреть промежуточный слой между интернет-банком и АБС.                                                   |
| R5      | Возможность переключения на резервный ЦОД                                           | Перенаправление трафика на другой ЦОД, который сможет принять нагрузку во время недоступности основного ЦОД     |
| P       | Производительность (Performance)                                                    |                                                                                                                 |
| P1      | Время отклика должно составлять единицы миллисекунд                                 | Сейчас некоторые справочные данные загружаются больше секунды.                                                  |
| P2      | Скорость работы с заявками не должна зависеть от объёма данных в АБС                | Учитывая перегруженность базы АБС, нужен кэширующий слой или отдельные микросервисы.                            |
| P3      | Горизонтальное масштабирование интернет-банка должно быть возможно                  | На текущем монолите сложно, но можно реализовать через API-шлюз и балансировку нагрузки.                        |
| P4      | Система должна выдерживать пиковые нагрузки (например, массовое открытие депозитов) | Необходимо тестирование на производительность и настройка пулов подключений.                                    |
| S       | Поддерживаемость (Supportability)                                                   |                                                                                                                 |
| S1      | Система должна быть легко обновляемой и расширяемой                                 | Документация, чистый код, разделение ответственностей.                                                          |
| S2      | Мониторинг состояния сервисов должен быть реализован                                | Логирование, метрики, оповещения.                                                                               |
| S3      | Должна быть возможность добавления новых продуктов без изменения ядра системы       | Гибкая конфигурация, например, через справочники в БД.                                                          |
| S4      | Система должна быть совместима с существующими технологиями банка                   | Использование MS SQL, Oracle, .NET Framework, Java Spring Boot.                                                 |
| S5      | Желательно использовать Kafka для очередей сообщений на перспективу                 | Но текущая версия интернет-банка несовместима с ней. Можно рассмотреть внедрение шины данных.                   |
| S6      | Разработка документации                                                             | Наличие, полнота и удобство системной документации и руководств                                                 |
| +R      | Ограничения (Restrictions)                                                          |                                                                                                                 |
| +R1     | Запрет на прямую интеграцию интернет-банка с АБС                                    | Из-за ограничений производительности и надёжности АБС.                                                          |
| +R2     | Ограничение на использование внешних платформ для расчёта ставок                    | Расчёт ставок должен происходить внутри банка.                                                                  |
| +R3     | Запрет на изменение ядра интернет-банка силами банка                                | Ядро принадлежит подрядчику, самостоятельные изменения невозможны.                                              |
| +R4     | Запрет на хранение персональных данных вне контролируемой среды                     | Все данные должны обрабатываться и храниться в рамках регуляторных требований РФ.                               |
| +R5     | Ограничение на вертикальное масштабирование АБС                                     | База данных АБС не поддерживает горизонтальное масштабирование.                                                 |
